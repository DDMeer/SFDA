总体判断

提案的核心贡献目前没有任何一项被完整实现。已实现的只有 Stage 1 流模型的前向/逆向机制本身（经验证确实可逆）。纤维插值算子 Z̄、双流架构、生成器的风格条件注入、分类器再训练、抗遗忘评测——全部缺失。

更关键的是两个会使现有实验结论失效的问题：其一，四个下游脚本中有三个把 z_s 当成了 z_c（第 8 节有逐通道追踪证据）；其二，Stage 1 的训练目标在交换两组通道下完全对称，因此没有任何梯度信号决定哪一组是"风格"——即使把接线全部改对，"解耦"在当前目标函数下依然无法成立。

此外，全流程（Stage 1 训练、Stage 2 训练、Stage 3 演示）都只使用 art_painting 一个域，仓库中不存在任何跨域实验、任何分类器训练代码、任何准确率数字。

当前系统实际做了什么

下图是从代码而非 README 还原的数据流。标 ✗ 处为实际接线与意图不符之处。

PACS art_painting  →  Resize(64×64), ToTensor  [0,1]，无 dequantization
   │
   ├─ Stage 1 ─ SimplifiedGlow
   │     squeeze: 3×64×64 → 12×32×32
   │     8 × [ Invertible1x1Conv(12) + AffineCoupling(12) ]
   │     split:  z_s = ch[0:4]   z_c = ch[4:12]
   │     loss = NLL + 5.0 · |Σ(∇ₓΣz_c ⊙ ∇ₓΣz_s)| / B      ✗ 对两组通道完全对称
   │     → checkpoints/glow_stage1.pth   [已核验: 8 层, 12 通道]
   │
   ├─ Stage 2 ─ ConceptBridge  8192 → 1024 → 512 → 512
   │     输入 = cat[ z_tensors[0], zeros ] = cat[ z_s , zeros ]   ✗ 应为 z_c
   │     目标 = CLIP ViT-B/32 文本嵌入（使用真实标签，监督）
   │     loss = MSE
   │     → checkpoints/bridge_stage2.pth [已核验: net.1 = 1024×8192]
   │
   ├─ Stage 3 ─ Stable Diffusion v1.5 img2img
   │     shadow = glow.reverse(zeros(8ch), z_s)                   ✗ 通道布局错乱
   │     label  = argmax softmax(bridge(z) @ CLIP_text.T)         ✗ 缺 logit_scale
   │     pipe(prompt=f"...{label}...", image=upscale(shadow,8×),
   │          strength=0.45, guidance=8.5)                        ✗ z_s 从未进入生成器
   │
   └─ Stage 4 ─ find_hard_samples()   15 行残桩，无 import，从未被调用

02 — 文件逐一说明

每个文件的职责与问题

models/

文件内容核验结果
glow_model.py SqueezeLayer / Invertible1x1Conv / AffineCoupling / SimplifiedGlow Squeeze 的正逆变换互为逆运算，已实测确认。1×1 卷积权重以 QR 正交初始化但作为自由参数训练，无正交约束，长训练可能趋于奇异。slogdet / inv 每次前向都强制搬到 CPU（MPS 不支持），造成同步阻塞。reverse() 不返回 logdet（无害）。
mapping_net.py StyleMapper: z_s → 768 维 死代码 且含潜在崩溃：默认 img_size=64，而 z_s 实际是 [B,4,32,32]（squeeze 后为 32×32）。若按默认构造，Linear 期望 16384 输入、实得 4096。另有空间错配见第 10 节。
classifier.py ResNet-50 + 新 fc 死代码 pretrained=True 在 torchvision 0.17 已弃用（仅告警）。提案中"用 ⟨X̂,Y⟩ 训练分类器"这一步完全没有对应的训练脚本。

scripts/

文件问题
stage1_train_glow.py 无 dequantization（像素为 256 级离散值，NLL 无下界，模型可将密度堆在格点上作弊）；无 ActNorm；无 logit 变换；无验证集；每 epoch 覆盖保存同一 checkpoint；DOMAIN 硬编码；JA 损失见第 9 节。
stage2_train_bridge.py 取到的是 z_s 而非 z_c（注释写着"提取 z_c (4通道)"，但模型返回顺序是 z_s, z_c, log_det）；对已归一化向量用 MSE（与余弦单调等价，但不如直接用余弦损失）；使用 art_painting 的真实标签监督训练，与 README "在缺失目标域标签的情况下"的说法矛盾。
stage3_generate.py z_c/z_s 完全对调；softmax 缺 logit_scale；每张图重新 clip.load()；四处 monkeypatch（cached_download、device_mesh、torch.xpu、_torch_available）绕过版本不兼容，脆弱；注释说"0.55 是黄金平衡点"但代码写 strength=0.45；shadow 从 64px 放大 8 倍到 512px，模糊到几乎不承载几何信息。
stage4_active_al.py 无任何 import（torch 未定义）；if entropy > threshold 对形状 [B] 的张量做布尔判断，B>1 时直接抛 RuntimeError；收集的 idx 是 batch 序号而非样本全局索引。三处错误叠加，说明这段代码从未运行过。
verify_stage1.py 解包错误导致 reverse() 参数含义反转；其 try/except "参数顺序兜底"永远不会触发，因为错误的调用通道数恰好也是 12，会静默成功。标题写 "Recon (zs=0)"，实际抹掉的是全部 content（第 8 节）。
visualize_zc.py 可视化的 4 个通道是 z_s，标题却是 "$z_c$ (The Content Base)"。注释"z_c 是 outputs 中的第一个 4 维张量"是整个 bug 家族的源头。
visual_verify.py 唯一正确 用 z_s, z_c, _ = transform_to_noise(x) 元组解包，reverse(z_s, z_c) 参数顺序也对。verification_results/*.png 是仓库中唯一可信的视觉证据。

其它

  • utils/jacobian_loss.py — 三重失效：z, _ = transform_to_noise(x) 把 3 个返回值解包成 2 个会抛 ValueError；model.reverse(z_perturbed) 缺第二个参数会抛 TypeError；split_dim=8 把 ch[0:8] 当风格，与模型的 ch[0:4] 相矛盾。从未被 import。
  • requirements.txt — 版本钉得完整且自洽（torch 2.2.2 / diffusers 0.27.0 / transformers 4.40.0 / numpy 1.26.4 避开 numpy 2 断裂 / CLIP 钉到具体 commit）。但 huggingface_hub 0.36.2 已移除 cached_download，这正是 Stage 3 需要 monkeypatch 的原因。
  • .gitignore 排除 data/，且本地无 data/ 目录 → 现有结果无法复现，需重新获取 PACS。
  • checkpoints/ — 两个权重均已加载核验，形状与代码定义一致。
  • results/ 2 张图（文件名含 4864），verification_results/ 5 张对比图。README 给出的复现命令是 --image data/art_painting/0/63.jpg，与已提交结果的文件名不对应；README 展示的输入图 demo/fig_3.jpg 是一张长颈鹿照片，而命令声称来自 art_painting 域的 0 类目录（按代码自带的 CLASS_MAP，0 = dog）。由于 data/ 未入库，无法判定是目录标签有误还是文档与产物不匹配，但两者至少有一处不一致。

三处误用同源：z_tensors = [t for t in outputs if t.dim()==4] 这个"稳健解包"启发式取 z_tensors[0] 当 z_c，但 transform_to_noise 的返回顺序是 (z_s, z_c, log_det)，所以 [0] 永远是 z_s。

Stage 2 的输入

cat[z_tensors[0], zeros] = cat[z_s(4ch), zeros(4ch)]。注意 Stage 2 与 Stage 3 的 bridge 输入构造方式彼此一致（都是"风格 + 零填充"），所以不存在训练/推理错配——bridge 只是从头到尾都在学一个错误的信号。

其它一致性问题

  • softmax 缺温度：stage3 对 [-1,1] 区间的余弦相似度直接取 softmax，未乘 CLIP 的 logit_scale（≈100）。用一组区分度良好的假想相似度复现，输出为 0.1457 / 0.1386 / 0.1516 / …，与 README 记录的 0.1469 / 0.1343 / 0.1609 / … 高度吻合。README 里那组"接近 1/7"的概率是温度缺失的产物，不能作为 bridge 失效的证据（argmax 不受温度影响）。bridge 实测并未坍缩：64 个差异极大的输入，输出两两余弦均值 0.59、有效秩 8。它的问题是输入错了，不是它学崩了。
  • CLIP 空间不统一：概念空间用 ViT-B/32（512 维），而 SD1.5 的交叉注意力条件空间是 ViT-L/14（768 维）。目前只传字符串所以尚未爆雷，但提案要求"语义基底作为控制条件"，这一步必须先统一。StyleMapper 输出 768 维正是为此准备的，却与 512 维的 bridge 对不上。
  • split_dim 矛盾：jacobian_loss.py 用 8:4（ch[0:8] 为风格），模型用 4:8（ch[0:4] 为风格），方向相反。
09 — 正交性

当前的正交损失对应几何正交吗？

简短回答：不对应。它是一个秩为 1 的代理量，且无法区分风格与语义。

提案要求的是：在每一点 e 处 T_eE = V_e ⊕ H_e 在黎曼度量下正交。设可逆映射 f: x ↦ (z_s, z_c)，这是关于雅可比块的条件：

J_s = ∂z_s/∂x ∈ R^(4096 × 12288)
J_c = ∂z_c/∂x ∈ R^(8192 × 12288)
垂直 ⊥ 水平  ⟺  J_s G J_cᵀ = 0     （G 为 x 空间的度量）
                 → 4096 × 8192 = 33,554,432 个标量约束

代码实现的是：

grad_c = ∇ₓ (Σ z_c)      # = J_cᵀ · 1      形状 (B,3,64,64)，一个向量
grad_s = ∇ₓ (Σ z_s)      # = J_sᵀ · 1      形状 (B,3,64,64)，一个向量
loss   = |Σ(grad_c ⊙ grad_s)| / B  =  |1ᵀ J_c J_sᵀ 1| / B

三个缺陷：

  1. 秩坍缩。两个雅可比都被全 1 向量收缩掉了，3355 万个约束只剩 1 个标量。实测梯度形状确认为 (B,3,64,64) 各一个向量。这只约束了一个方向上的相关性。
  2. 符号抵消。abs 在跨样本、跨像素求和之后才取，正负项可以互相抵消。损失为零不蕴含正交——对称噪声就能让它归零。应改为逐样本平方和或逐样本取绝对值再平均。
  3. 角色对称。L(z_c, z_s) = L(z_s, z_c)。而 NLL 对通道划分同样不变。因此 Stage 1 的整个目标函数在交换两组通道下完全不变——没有任何梯度告诉模型 ch[0:4] 应该是"风格"。这两个名字是纯粹的命名约定，背后没有训练信号。
这是最根本的问题

第 3 点独立于所有接线 bug。即使把第 8 节的三处误用全部修正，当前目标函数下的"解耦"依然不成立，因为没有任何东西把类别信息推进 z_c。必须引入一项打破对称性的、只作用于 z_c 的语义损失（例如把 CLIP 对齐或分类头与 Stage 1 联合训练）。

另外，代码中没有指定任何度量 G，隐含使用像素空间的欧氏内积——所以提案里的"黎曼度量"目前不承担任何计算内容。utils/jacobian_loss.py 里的随机投影版本方向是对的（能解决缺陷 1、部分解决 2），但它已失效且未被调用。正确的估计量是：

E_{v,w~N(0,I)} [ ((J_sᵀ v) · (J_cᵀ w))² ]     # 用 vjp 估计
   = ‖J_c J_sᵀ‖_F² 的无偏估计 —— 正是块正交条件本身
10 — 生成器条件

生成器真的以 z_s 为条件吗？

没有。grep 确认 z_s 从未到达 pipe()。

传入 SD pipeline 的全部内容只有三项：

  • prompt — f"a realistic high-quality photo of a {label}, cinematic lighting, 8k, highly detailed"。它对隐变量的依赖只经过一个 argmax 标签，信息量 log₂7 ≈ 2.8 bit。
  • image — 64×64 的重构图放大 8 倍到 512×512，极度模糊。
  • strength=0.45, guidance_scale=8.5 — 常数。

风格在流程中被置零移除，之后从未重新注入。因此当前管线的本质是"内容 → 类别标签 → 通用照片 prompt"，属于基于提示词的域随机化，而不是提案所说的纤维受控生成。StyleMapper（本应是 z_s 的注入接口）存在但零引用，且带有第 2 节的形状缺陷和第 8 节的 512/768 空间错配。

信息瓶颈

整套几何计算的产物，最终被压缩成 (a) 2.8 bit 的类别标签 和 (b) 一张 8 倍上采样的 64px 模糊图。在这个配置下，"生成数据保留了底流形语义"这一主张在原理上就无法被检验——因为几乎没有几何信息传递到生成器。

11 — 纤维插值

纤维插值/扰动实现了吗？

没有。α、β、任何两样本之间的插值，全仓库零实现。

最接近的两处都在 visual_verify.py，且都在任何训练路径之外：

x_style_up    = model.reverse(z_s * 1.5, z_c)          # 单样本风格的标量缩放
z_s_random    = torch.randn_like(z_s) * 0.3
x_random_style = model.reverse(z_s_random, z_c)        # 用噪声整体替换风格

两者都不是"两个样本风格之间的插值"。仓库中不存在 z_s1/z_s2 的配对逻辑、不存在难/易样本划分、不存在 Δ 网络、不存在 β 系数。而且这两行的输出只被存成一张 PNG 网格，从未用于生成训练数据。

对照提案：Z̄ = αZ_h^s + (1−α)Z_e^s + βΔ_Z 是整个可计算方案的核心创新，它的实现度为 0。

P2

方法论与理论强度

决定这是"又一个解耦方法"还是有独特论点
  1. 让"垂直"这一主张可证伪。在真实域对上测量 ρ = E[‖P_V(f_t − f_s)‖ / ‖f_t − f_s‖]。这一个数字就能把纤维丛叙事从定义变成可检验假设，而且成本极低。目前的论证是"把域偏移定义为垂直运动，再推出底流形不变"，是恒等式而非定理。
  2. 把 Δ_Z 投影到垂直子空间。否则扰动会离开纤维、改变语义，⟨X̂, Y⟩ 沿用原标签就失去理论依据。这是一条能把几何直接翻译成损失项的具体改动。
  3. 正视局部平凡性。固定通道划分的 INN 实现的是全局平凡丛，而提案正文写的是"局部同胚"。要么改用条件耦合层/局部图册，要么测量和乐（让风格沿域回路输运一圈，测返回误差）并把它作为丛是否平凡的证据。这是目前最有分量的差异化点。
  4. 明确度量 g。若就是欧氏度量，直说并去掉"黎曼"二字；若要它承担内容，用拉回度量（Fisher / 分类器诱导），这同时会改变正交损失的形式。
  5. 正面处理可辨识性。明确声明 B 由文本嵌入子流形锚定，这正是提供可辨识性的归纳偏置（可引 Locatello 等的不可能性结果）。
  6. 防范伪标签污染。SFDA 中难样本的伪标签本就不可靠，其风格特征可能混入内容，需在 Z_h 的使用上加置信度门控。
